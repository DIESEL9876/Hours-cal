# Hours-Cal — הוראות רישוי, הפעלה וגיבוי (לבעל התוכנה)

המסמך מיועד לבעל התוכנה, עילי נגר.

> **מומלץ: Hours-Cal License Manager.** תוכנה גרפית בעברית שמבצעת את כל השלבים במסמך זה בלחיצות, בלי שורת פקודה: יצירת מפתח מוגן בהגנת Windows, הנפקה, רשומת רישיונות וגיבוי מוצפן. ראו [LICENSE_MANAGER_GUIDE_HE.md](LICENSE_MANAGER_GUIDE_HE.md). כלי שורת הפקודה שמתואר כאן נשאר כחלופה. מפתח שנוצר בו ניתן לייבא למנהל הרישיונות, וכל הרישיונות שכבר הונפקו בו ימשיכו לפעול.

העיקרון: **קודם מנפיקים לעצמך רישיון ומתקינים אותו, ורק אחר כך מתקינים גרסה שאוכפת את דרישת הרישיון.** כך המחשב שלך לא יינעל לרגע.

## איך זה בנוי

| רכיב | תפקיד |
|---|---|
| **Hours-Cal 1.1.3** (קובץ ההתקנה `Hours-Cal_1.1.3_x64-setup.exe`) | מציג את הסכם הרישיון, תנאי השימוש ומדיניות הפרטיות בהתקנה ראשונה ופעם אחת אחרי כל עדכון גרסה. כולל מסך "מסמכים משפטיים ורישיון" והודעות זכויות יוצרים. **בגרסה זו דרישת הרישיון עדיין לא מופעלת**, כי המפתח הציבורי שלך טרם הוטמע בה. העבודה עם הנתונים נמשכת כרגיל. |
| **כלי הרישוי** (`hourscal-license-tool.exe`) | תוכנה נפרדת לשימושך בלבד. יוצרת את מפתח החתימה, מציגה את מזהה המחשב ומנפיקה רישיונות. **לעולם לא נכללת בקובץ ההתקנה ולא נשלחת ללקוחות.** |
| **גרסה אוכפת** | נבנית מאותו קוד אחרי שהמפתח הציבורי שלך (`license_public_key.txt`) מועתק לפרויקט. רק בה נדרש רישיון. |

מיקומי הקבצים במחשב:

- **נתוני העסקים, העובדים והנוכחות:** `%APPDATA%\il.office.hourscal\hours-cal.sqlite3`. הגיבויים נמצאים בתיקייה `backups` שלידו. מיקום זה לא השתנה.
- **נתוני ההסכם והרישיון:** `%LOCALAPPDATA%\il.office.hourscal\licensing\`. הם נשמרים בנפרד מהנתונים ומהגיבויים, ולכן גיבוי ושחזור לא משפיעים עליהם.

## שלב 0 — גיבוי לפני הכול

1. ב-Hours-Cal: **גיבוי ונתונים ← יצירת גיבוי עכשיו**.
2. סגור את התוכנה והעתק את כל התיקייה `%APPDATA%\il.office.hourscal` לכונן חיצוני.
3. שמור בצד את קובץ ההתקנה של הגרסה הנוכחית (1.1.1), כדי שתמיד אפשר יהיה לחזור אליה.

## שלב 1 — יצירת מפתח החתימה (פעם אחת בלבד, במחשב שלך)

1. העתק את `hourscal-license-tool.exe` לתיקייה מחוץ לכל פרויקט, רצוי לדיסק-און-קי מוצפן (BitLocker To Go). הכלי אינו דורש התקנה.
2. פתח PowerShell באותה תיקייה והרץ:
   ```
   .\hourscal-license-tool.exe keygen --dir E:\HoursCal-Keys
   ```

נוצרים שני קבצים:

| קובץ | מה עושים איתו |
|---|---|
| `hourscal-signing-key.PRIVATE.txt` | **המפתח הפרטי.** שמור אותו בשני עותקים לא מקוונים ומוצפנים, במקומות שונים. אל תשלח אותו במייל או בצ'אט, אל תעלה אותו ל-GitHub ואל תשמור אותו בתיקיית הפרויקט. אם הוא אובד, לא ניתן יהיה להנפיק רישיונות שיתקבלו בגרסאות הקיימות. |
| `license_public_key.txt` | **המפתח הציבורי.** אין בו סוד. הוא מוטמע בגרסה האוכפת (שלב 5). |

הכלי מסרב ליצור מפתח בתוך תיקייה של מאגר git, ומסרב לדרוס מפתח קיים.

## שלב 2 — הנפקת הרישיון שלך

```
.\hourscal-license-tool.exe device-id
```
מוצג מזהה ההפעלה של המחשב, למשל `HC1-VM1F-VGQJ-6V39-54CA-1EFZ-CX77`.

```
.\hourscal-license-tool.exe issue --key E:\HoursCal-Keys\hourscal-signing-key.PRIVATE.txt --device HC1-VM1F-VGQJ-6V39-54CA-1EFZ-CX77 --licensee "עילי נגר" --out E:\owner.hclic
```

הכלי:
- חותם על הרישיון.
- בודק אותו בעצמו בדיוק כפי שהאפליקציה תבדוק.
- שומר את הקובץ `owner.hclic`.
- רושם את ההנפקה בקובץ `issued-licenses.csv` שליד המפתח.

## שלב 3 — התקנת Hours-Cal 1.1.3 ואישור ההסכם

1. הרץ את `Hours-Cal_1.1.3_x64-setup.exe`. ההתקנה מעדכנת את הגרסה הקיימת, והנתונים נשארים במקומם.
2. אם תופיע בהסרה אפשרות למחיקת נתוני האפליקציה, **אל תסמן** אותה.
3. בפתיחה הראשונה מוצגים הסכם הרישיון, תנאי השימוש ומדיניות הפרטיות.
   - סמן "קראתי את הסכם הרישיון, תנאי השימוש ומדיניות הפרטיות ואני מסכים/ה להם".
   - לחץ **אישור קריאה והסכמה**, ואחר כך **המשך לאפליקציה**.
4. רשימת העסקים נפתחת עם כל הנתונים.

ההסכם יוצג שוב רק אחרי עדכון גרסה. הוא לא יוצג בפתיחה רגילה, אחרי הפעלה מחדש של המחשב, או אחרי גיבוי ושחזור. אם תלחץ "אינני מסכים/ה", התוכנה תיסגר ושום נתון לא יימחק.

## שלב 4 — התקנת הרישיון שלך (לפני שדרישת הרישיון מופעלת)

1. בתפריט העליון: **מסמכים משפטיים ורישיון**.
2. ודא שמזהה ההפעלה המוצג זהה למזהה שקיבלת בשלב 2.
3. לחץ **ייבוא קובץ רישיון** ובחר את `owner.hclic`. לחלופין, הדבק את מפתח ההפעלה ולחץ **שמירת הרישיון**.
4. המצב יהיה "רישיון שמור – החתימה תאומת כאשר דרישת הרישיון תופעל".
   - בגרסה זו נבדקים מבנה הרישיון, התאמתו למחשב ותוקפו.
   - החתימה עצמה נבדקת אוטומטית בכל פתיחה של הגרסה האוכפת.

## שלב 5 — הפעלת דרישת הרישיון (גרסה אוכפת)

1. העתק **רק** את `license_public_key.txt` לפרויקט, לנתיב `src-tauri\keys\license_public_key.txt`, במקום הקובץ הקיים. אפשר גם לשלוח את תוכן הקובץ (שורה אחת) לבנייה. זה בטוח, כי זה המפתח הציבורי בלבד.
2. בנה את קובץ ההתקנה: `npm run tauri build` ב-Windows, או דרך GitHub Actions שבונה אוטומטית. מומלץ להעלות את מספר הגרסה, למשל ל-1.1.4.
3. התקן את הגרסה האוכפת. אם מספר הגרסה עלה, ההסכם יוצג פעם אחת. לאחר מכן התוכנה נפתחת ישר לרשימת העסקים, כי הרישיון שהתקנת בשלב 4 מאומת.
4. במסך **מסמכים משפטיים ורישיון** יופיע "רישיון תקף ומאומת".

**אם משהו לא עובד** (למשל הוטמע מפתח ציבורי שאינו תואם):
- יוצג מסך "הפעלת רישיון" עם הסיבה.
- הנתונים לא נמחקים ולא משתנים.
- אפשר לייבא שוב את `owner.hclic`.
- אפשר ללחוץ **ייצוא נתונים קיימים (קריאה בלבד)**.
- אפשר להתקין שוב את 1.1.3 שאינה אוכפת.

## שלב 6 — הנפקת רישיונות למחשבים אחרים

1. הלקוח מתקין את Hours-Cal ומאשר את ההסכם.
2. הלקוח מעתיק את מזהה ההפעלה ושולח לך אותו. המזהה מוצג במסך ההפעלה, או במסך **מסמכים משפטיים ורישיון**.
3. אתה מריץ:
   ```
   .\hourscal-license-tool.exe issue --key <המפתח הפרטי> --device <המזהה של הלקוח> --licensee "שם הלקוח" --org "שם העסק"
   ```
   לרישיון לתקופה מוגבלת מוסיפים `--expires 2027-12-31`. התוקף כולל את היום האחרון. בלי הפרמטר הזה הרישיון לצמיתות.
4. שלח ללקוח את קובץ ה-`.hclic`. הלקוח מייבא אותו.

רישיון שהונפק למחשב אחד נדחה בכל מחשב אחר, גם אם מעתיקים את הקובץ או משחזרים גיבוי.

## שלב 7 — החלפת מחשב, תיקון או התקנה מחדש של Windows

- **הסרה והתקנה מחדש של Hours-Cal באותו Windows:** מזהה ההפעלה לא משתנה.
- **החלפת מחשב, התקנה מחדש של Windows, או איפוס:** המזהה משתנה. במקרה כזה:
  1. הלקוח שולח את המזהה החדש.
  2. בקובץ `issued-licenses.csv` מוצאים את מספר הרישיון הישן.
  3. מנפיקים רישיון חלופי:
     ```
     .\hourscal-license-tool.exe issue --key <המפתח> --device <המזהה החדש> --licensee "שם הלקוח" --replaces HCL-2026-XXXXXXXXXX
     ```
  4. אפשרות נוספת: מוסיפים את מספר הרישיון הישן לקובץ `src-tauri\keys\revoked-licenses.txt`. הרישיון ייחסם בגרסה הבאה שתיבנה. מנגנון לא מקוון לא יכול לבטל רישיון במחשב שלא מתעדכן.
- **הנתונים לעולם לא ננעלים:** גם בלי רישיון תקף אפשר לייצא את כל הנתונים במצב קריאה בלבד.

## שלב 8 — גיבוי ושחזור

- **גיבוי ושחזור:** כמו קודם, דרך **גיבוי ונתונים**. הם לא מציגים שוב את ההסכם ולא משפיעים על הרישיון.
- **העברת נתונים למחשב חדש:** משחזרים את הגיבוי במחשב החדש. במחשב החדש נדרשים אישור הסכם ורישיון משלו (שלב 7).
- **ייצוא במצב שחזור** (כשהרישיון חסר או לא תקף, בגרסה האוכפת): לוחצים **ייצוא נתונים קיימים (קריאה בלבד)** במסך ההפעלה ובוחרים תיקייה. נשמרים:
  - קובץ CSV לכל טבלה.
  - עותק מלא של מסד הנתונים.
  - קובץ הסבר.

  מסד הנתונים המקורי לא נפתח לעריכה ולא משתנה.

## מזהה ההפעלה — מה הוא ומה מגבלותיו

- המזהה מחושב בגיבוב SHA-256 מתוך `MachineGuid` של Windows, בתוספת מחרוזת ייחודית ל-Hours-Cal.
- ה-GUID הגולמי לא מוצג, לא נשמר ולא נשלח. המזהה לא כולל שם משתמש, שם מחשב, כתובת רשת או פרטי חומרה.
- **יציב:** בהסרה והתקנה מחדש של Hours-Cal ובעדכוני גרסה.
- **משתנה:** בהתקנה מחדש של Windows ובאיפוס המחשב.
- **מגבלות ידועות:**
  - מחשבים ששוכפלו מאותה תמונת דיסק בלי sysprep עשויים לקבל מזהה זהה.
  - מנהל מערכת יכול לשנות את הערך ברישום (Registry).
  - המנגנון מספק הגנה משמעותית, אך אין מנגנון שלא ניתן לפרוץ.
- אם לא ניתן לקרוא את `MachineGuid`, נוצר מזהה מקומי (`HCF-...`). מזהה כזה משתנה אם תיקיית `licensing` נמחקת.

## לפני הפצה ללקוחות — רשימת בדיקה

1. מלא כתובת דוא״ל רשמית בקובץ `legal\release-config.json` בשדה `contact_email`.
   - עד אז מוצג בהסכם "[כתובת דוא״ל להשלמה לפני ההפצה]".
   - שינוי הכתובת משנה את טביעת האצבע של הנוסח, ולכן כל משתמש יאשר את ההסכם המעודכן פעם אחת.
2. הטמע את המפתח הציבורי (שלב 5).
3. הרץ `npm run check:release`. הבדיקה נכשלת אם חסרים כתובת הדוא״ל או המפתח הציבורי.
4. העבר את נוסח ההסכם (`legal\agreement_he.md`) לבדיקת עורך דין. זו טיוטה שטרם אושרה משפטית.
5. בדוק שמדיניות הפרטיות נכונה. האפליקציה עצמה אינה מתחברת לאינטרנט. קובץ ההתקנה עשוי להוריד את רכיב WebView2 של Microsoft, אם הוא חסר במחשב.
6. ודא שקובצי הרישיון של רכיבי הקוד הפתוח נכללים בהתקנה.
