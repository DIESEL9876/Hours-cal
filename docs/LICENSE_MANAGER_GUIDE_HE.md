# Hours-Cal License Manager — מדריך לבעל התוכנה

**Hours-Cal License Manager** ("מנהל הרישיונות") היא תוכנת Windows נפרדת, עם ממשק גרפי בעברית, שבה מנפיקים ומנהלים רישיונות Hours-Cal בכמה לחיצות, בלי שורת פקודה.

- התוכנה מיועדת **לבעל התוכנה בלבד**.
- היא **אינה** נכללת בהתקנת Hours-Cal ואינה נשלחת ללקוחות.
- קובץ ההתקנה שלה: `Hours-Cal License Manager_1.0.0_x64-setup.exe`.

## 1. עקרונות האבטחה

**מפתח החתימה הפרטי:**
- נוצר **במחשב שלך בלבד**, בלחיצה במנהל הרישיונות. הוא לא נוצר בענן, ב-GitHub או אצל מי שבונה את התוכנה.
- נשמר מוצפן בהגנת Windows (DPAPI) לחשבון המשתמש שלך. רק אותו משתמש Windows, באותו מחשב, יכול לפענח אותו.
- לא מוצג במסך, לא נכתב ליומנים, ולא נכלל בקבצי רישיון, בקובץ המפתח הציבורי, ברשומות או בצילומי מסך.
- יוצא מהמחשב רק כ**גיבוי מוצפן בסיסמה**, ורק כשאתה מבקש זאת במפורש.

**חתימה ובדיקה:**
- כל פעולות המפתח (יצירה, חתימה, הצפנת גיבוי) מתבצעות ברכיב ה-Rust המקומי, ולא בממשק.
- כל רישיון נבדק מיד לאחר החתימה, בדיוק כפי ש-Hours-Cal תבדוק אותו. רק אחרי הבדיקה הוא נשמר.

**מפתח אחד לתמיד:**
- אותו מפתח משמש לכל הרישיונות, לתמיד. אין צורך לבנות מחדש את Hours-Cal לכל לקוח.
- התוכנה **לעולם לא יוצרת מפתח חדש מעצמה**.
- אם המפתח שהוגדר אינו זמין (Windows הותקן מחדש, משתמש אחר, קובץ נמחק), יוצג מסך שחזור. יצירת מפתח חלופי דורשת להקליד במפורש `מפתח חדש`.

**ללא אינטרנט:** התוכנה פועלת ללא חיבור לאינטרנט. הרשומות נשמרות במחשב שלך.

<a id="התקנה"></a>
## 2. התקנה והגדרה ראשונה

1. הרץ את `Hours-Cal License Manager_1.0.0_x64-setup.exe`.
   - ההתקנה למשתמש הנוכחי בלבד ואינה דורשת הרשאות מנהל.
   - אם WebView2 חסר, הוא יותקן אוטומטית (נדרש אינטרנט פעם אחת).
2. פתח את **Hours-Cal License Manager** מתפריט התחל. יוצג מסך "ברוכים הבאים". בחר אחת משלוש האפשרויות:

| אפשרות | מתי |
|---|---|
| **יצירת מפתח חתימה חדש** | הפעם הראשונה, ואין לך מפתח קיים. סמן "קראתי והבנתי" ← **יצירת המפתח**. |
| **שחזור מקובץ גיבוי** | יש לך קובץ `‎.hckeybak‎` ממנהל הרישיונות, למשל במעבר למחשב חדש. |
| **ייבוא מפתח מכלי שורת הפקודה** | כבר יצרת מפתח בכלי `hourscal-license-tool` (קובץ `hourscal-signing-key.PRIVATE.txt`). כל הרישיונות שכבר הנפקת בו ימשיכו לפעול. |

לאחר יצירת המפתח או ייבואו נפתח מיד חלון **גיבוי מפתחות** (סעיף 3).

**אם ייבאת מפתח מכלי שורת הפקודה:**
1. שמור גיבוי של מנהל הרישיונות (סעיף 3).
2. ודא שהגיבוי נשמר.
3. מחק את קובץ ה-`PRIVATE` המקורי מכל מקום לא מוצפן.

<a id="גיבוי"></a>
## 3. גיבוי מפתחות — מיד אחרי ההגדרה

כל עוד לא נשמר גיבוי, מוצגת במסך הראשי הודעה צהובה: "עדיין לא נשמר גיבוי של מפתח החתימה".

1. לחץ **גיבוי מפתחות**.
2. בחר סיסמת גיבוי באורך **12 תווים לפחות**. מומלץ משפט ארוך. הקלד אותה פעמיים.
3. סמן "רשמתי את הסיסמה במקום בטוח…".
4. לחץ **בחירת מיקום ושמירת הגיבוי** ובחר מיקום, רצוי דיסק-און-קי.
5. התוכנה מצפינה את הגיבוי, פותחת אותו שוב לבדיקה עם הסיסמה, ומאשרת: "הגיבוי נוצר ונבדק".

**מה הגיבוי כולל:** המפתח הפרטי ורשומת הרישיונות המלאה, מוצפנים ב-Argon2id + XChaCha20-Poly1305. כל שינוי בקובץ יגרום לדחייתו.

**כללים:**
- שמור **שני עותקים** במקומות שונים (למשל שני דיסקים חיצוניים). שמור את הסיסמה בנפרד מהקובץ.
- **אין דרך לשחזר סיסמה שנשכחה.**
- מומלץ לשמור גיבוי חדש מדי פעם, כדי שגם רשומות הרישיונות החדשות יגובו. המפתח עצמו אינו משתנה.

<a id="הפעלה"></a>
## 4. הפעלת המחשב שלך והפעלת דרישת הרישיון ב-Hours-Cal

כרגע (גרסה 1.1.3) **Hours-Cal עדיין לא דורשת רישיון**, כי המפתח הציבורי שלך טרם הוטמע בה. הסדר הנכון הוא: קודם מתקינים לעצמך רישיון, ורק אחר כך בונים גרסה שאוכפת את הדרישה. כך המחשב שלך לא יינעל לרגע.

### שלב א' — רישיון למחשב שלך
1. במנהל הרישיונות: **פרטי המחשב שלי**. מוצג "מזהה ההפעלה של מחשב זה" (מתחיל ב-`HC1-`). זה אותו מזהה ש-Hours-Cal מציגה במחשב הזה.
2. לחץ **הנפקת רישיון למחשב זה**. המזהה וכינוי המחשב ממולאים אוטומטית.
3. הזן את שמך, השאר "קבוע (ללא הגבלת זמן)" ולחץ **הפקת הרישיון**.
4. לחץ **הצגה בתיקייה**. הקובץ נשמר בתיקייה `מסמכים\Hours-Cal Licenses`.

### שלב ב' — התקנת הרישיון ב-Hours-Cal הנוכחית
1. פתח את Hours-Cal 1.1.3 ← **מסמכים משפטיים ורישיון** ← **ייבוא קובץ רישיון** ← בחר את קובץ ה-`‎.hclic‎`.
2. הגרסה הנוכחית שומרת את הרישיון ומציגה: "רישיון שמור – החתימה תאומת כאשר דרישת הרישיון תופעל".

### שלב ג' — מסירת המפתח הציבורי לפרויקט Hours-Cal
1. ב**פרטי המחשב שלי** לחץ **שמירת license_public_key.txt**.
   - הקובץ מכיל **רק את המפתח הציבורי**, בשורת הערה ובשורת מפתח אחת.
   - זה קובץ לא סודי, ומותר להעלות אותו ל-GitHub.
2. החלף בו את הקובץ `src-tauri/keys/license_public_key.txt` בפרויקט Hours-Cal. דרכים לעשות זאת:
   - ב-GitHub: פתח את הקובץ ← עריכה ← הדבק את התוכן ← Commit.
   - או: העבר את תוכן הקובץ, שהוא שורה אחת, למי שבונה את הגרסה.

### שלב ד' — בניית הגרסה האוכפת
1. העלה את מספר הגרסה, למשל ל-**1.1.4**, בשלושה קבצים: `package.json`, `src-tauri/tauri.conf.json` ו-`src-tauri/Cargo.toml`.
2. בנה את ההתקנה בדרך הרגילה:
   - **GitHub Actions:** התהליך "Test and build" מפיק את `Hours-Cal_1.1.4_x64-setup.exe`.
   - **או ב-Windows:** `npm ci` ואחריו `npm run tauri build`.
3. לפני הפצה ציבורית הרץ `npm run check:release`. הבדיקה נכשלת אם המפתח הציבורי אינו מוטמע, או אם כתובת הדוא"ל המשפטית (`legal/release-config.json`) עדיין ריקה.

### שלב ה' — בדיקה במחשב שלך, ורק אז הפצה
1. התקן את 1.1.4 במחשב שלך. ההסכם יוצג פעם אחת, והתוכנה תיפתח **ישר לרשימת העסקים, בלי בקשת הפעלה**.
2. ב**מסמכים משפטיים ורישיון** יופיע "רישיון תקף ומאומת".
3. רק לאחר מכן הפץ את הגרסה ללקוחות.

**אם בשלב ה' מוצג מסך "הפעלת רישיון":**
- הנתונים לא נמחקים.
- ייבא שוב את קובץ ה-`‎.hclic‎`.
- ודא שהמפתח הציבורי שהוטמע הוא זה שבמסך **פרטי המחשב שלי**. מזהה המפתח (`k-…`) חייב להיות זהה.
- תמיד אפשר להתקין שוב את 1.1.3 שאינה אוכפת.

> תהליך זה (הנפקה במנהל הרישיונות ← ייבוא בגרסה שאינה אוכפת ← גרסה אוכפת עם המפתח המיוצא נפתחת ישר) נבדק בבדיקה האוטומטית `own_computer_activation_workflow_before_enforcement`.

<a id="הנפקה"></a>
## 5. הנפקת רישיון ללקוח

1. הלקוח מתקין את Hours-Cal ומאשר את ההסכם.
2. הלקוח מעתיק את **מזהה ההפעלה של מחשב זה** ממסך "הפעלת רישיון" ושולח לך אותו.
3. במנהל הרישיונות לחץ **הפקת רישיון חדש** ומלא:

| שדה | הסבר |
|---|---|
| שם בעל הרישיון / החברה | חובה. מופיע ברישיון וב-Hours-Cal. |
| מזהה ההפעלה של המחשב | חובה. אפשר להדביק גם באותיות קטנות או עם רווחים. מזהה לא תקין נדחה ולא נוצר קובץ. |
| כינוי המחשב | לא חובה, לזיהוי ברשומות שלך בלבד. למשל "מחשב קבלה". |
| סוג הרישיון | **קבוע**, או **מוגבל בזמן** עם תאריך תפוגה. הרישיון פועל עד סוף היום שנבחר, כולל. יש קיצורים: חודש, 3 חודשים, שנה. |
| הערות | לא חובה. נשמרות ברשומות שלך בלבד ואינן נכללות בקובץ הרישיון. |

4. לחץ **הפקת הרישיון**. הרישיון נחתם, נבדק, נשמר כקובץ `<שם> - <מספר רישיון>.hclic` ונרשם ברשומות.
5. בחלון שנפתח אפשר:
   - **הצגה בתיקייה** — לפתיחת התיקייה עם הקובץ.
   - **העתקת פרטי הרישיון** — טקסט מוכן לשליחה ללקוח, כולל הוראות הפעלה.
   - **העתקת מפתח ההפעלה** — חלופה לקובץ.
6. שלח ללקוח את הקובץ. הלקוח בוחר ב-Hours-Cal **ייבוא קובץ רישיון**.

**מספר הרישיונות אינו מוגבל**, ולא צריך לבנות מחדש את Hours-Cal.

<a id="רשומה"></a>
## 6. רשומת הרישיונות

המסך הראשי מציג מונים (סה"כ, קבועים, מוגבלים בזמן, בתוקף, פג תוקף, מבוטלים/הוחלפו) וטבלה של כל הרישיונות.

**חיפוש וסינון:**
- **חיפוש** לפי שם, מספר רישיון, מזהה מחשב (גם בלי מקפים), כינוי או הערות.
- **סינון** לפי סוג ולפי סטטוס.

**סטטוסים:**

| סטטוס | משמעות |
|---|---|
| **בתוקף** | החתימה תקינה עם המפתח שלך והרישיון בתוקף. |
| **פג תוקף** | רישיון מוגבל בזמן שתאריכו עבר. Hours-Cal חוסמת אותו מעצמה. |
| **הוחלף** | הונפק רישיון חלופי במקומו. |
| **מבוטל** | סימנת אותו כמבוטל. ראה מגבלות בסעיף 8. |
| **לא ניתן לאימות** | נחתם במפתח אחר (למשל רשומה מגיבוי של מפתח אחר) או שהנתונים פגומים. |

הסטטוס מחושב מחדש בכל הצגה, מתוך החתימה והתאריכים. הוא לא נשמר כטקסט.

**לחיצה על שורה** פותחת חלון פרטים. בחלון:
- כל השדות, מפתח החתימה ומיקום הקובץ המקורי.
- **היסטוריית החלפות**: לחיצה על מספר רישיון במעבר אליו.
- **פעולות:** העתקת פרטים או מפתח הפעלה, הצגה בתיקייה, **ייצוא קובץ מחדש** (נבדק שוב לפני השמירה), **הנפקת רישיון חלופי**, **סימון כמבוטל** או ביטול הסימון.

**תיקיית הקבצים:** ברירת המחדל לקבצי ה-`‎.hclic‎` היא `מסמכים\Hours-Cal Licenses`. ניתן לשנות אותה ב**פרטי המחשב שלי ← מיקומי קבצים**.

<a id="החלפה"></a>
## 7. החלפת מחשב ורישיון חלופי

כאשר לקוח מחליף מחשב, מתקין מחדש את Windows או משנה חומרה מהותית, מזהה ההפעלה משתנה.

1. בקש מהלקוח את המזהה החדש.
2. פתח את הרישיון הקודם ← **הנפקת רישיון חלופי**. השם, הסוג והתוקף ממולאים מראש.
3. הזן את המזהה החדש ← **הפקת הרישיון**.

הרישיון הקודם יסומן "הוחלף", וההיסטוריה תוצג בשני הרישיונות. אי אפשר להנפיק רישיון חלופי לאותו מזהה מחשב.

**נתוני הלקוח** (עסקים, עובדים, נוכחות) אינם קשורים לרישיון ואינם נפגעים.

<a id="ביטול"></a>
## 8. ביטול רישיון — ומה אי אפשר

הרישיונות פועלים **ללא חיבור לאינטרנט**. לכן:

- **אין ביטול מרחוק ומיידי.** "סימון כמבוטל" מעדכן רק את הרשומות שלך.
- כדי לחסום רישיון בפועל:
  1. במסך הראשי לחץ **ייצוא רשימת ביטולים** ושמור את `revoked-licenses.txt`.
  2. החלף בו את `src-tauri/keys/revoked-licenses.txt` בפרויקט Hours-Cal.
  3. בנה גרסה חדשה והפץ אותה.
- הביטול חל **רק במחשבים שיתקינו את הגרסה החדשה**. מחשב שלא יעודכן ימשיך לפעול עם הרישיון שלו.
- רישיון **מוגבל בזמן** נעצר מעצמו בתאריך התפוגה. זו הדרך האמינה להגביל שימוש, למשל בתקופת ניסיון.

<a id="שחזור"></a>
## 9. מעבר למחשב חדש ושחזור

1. התקן את מנהל הרישיונות במחשב החדש.
2. במסך הפתיחה בחר **שחזור מקובץ גיבוי**. אפשר גם בכל עת: **שחזור מפתחות**.
3. בחר את קובץ ה-`‎.hckeybak‎`. יוצג מזהה המפתח שבו, לפני הזנת הסיסמה.
4. הזן את הסיסמה ← **שחזור**. המפתח יישמר בהגנת Windows במחשב החדש, ורשומות הרישיון יתווספו. רשומות קיימות אינן משתנות.

**הגנות בשחזור:**
- סיסמה שגויה או קובץ ששונה: "הסיסמה שגויה או שקובץ הגיבוי פגום או שונה. לא שוחזר דבר."
- אם במחשב כבר פעיל **מפתח אחר**, השחזור נחסם. אי אפשר להחליף מפתח פעיל.
- אם במחשב הוגדר בעבר מפתח אחר שאינו זמין, השחזור דורש להקליד `מפתח חדש`.

**אם Windows הותקן מחדש באותו מחשב:** הגנת DPAPI הקודמת אובדת. התוכנה תציג "מפתח החתימה אינו זמין במחשב זה". שחזר מהגיבוי.

## 10. מה מותר ומה אסור לשתף

| מותר | אסור |
|---|---|

<a id="טכני"></a>
## 12. פרטים טכניים

**מבנה:**
- Tauri 2 + React. רכיב ה-Rust משתמש בספריית הרישוי הקיימת `crates/hourscal-license` ללא שינוי בפרוטוקול: Ed25519, טוקן `payload.signature`, מזהי מחשב `HC1-`.
- הליבה נמצאת ב-`crates/hourscal-license-manager`, הממשק ב-`license-manager/`.
- הפונקציה שמפענחת את המפתח הפרטי (`Vault::signing_key`) פנימית לליבה. אף פקודה בממשק לא מחזירה אותו.

**נתונים** (`%LOCALAPPDATA%\il.owner.hourscal.licensemanager\`):

| קובץ | תוכן |
|---|---|
| `keys\owner-signing-key.json` | המפתח הפרטי מוצפן ב-DPAPI (משתמש נוכחי, עם entropy ייחודי) |
| `owner-profile.json` | מזהה המפתח שהוגדר. מונע יצירה שקטה של מפתח חדש |
| `license_public_key.txt` | המפתח הציבורי |
| `registry.sqlite3` | רשומת הרישיונות, ההגדרות ויומן הפעולות |

**תאימות:** פורמט קובץ המפתח הציבורי זהה בבייטים לזה של כלי שורת הפקודה. רישיונות שהונפקו בכל אחד מהכלים נבדקים בהצלחה בשני. נבדק אוטומטית ב-`crates/hourscal-license-tool/tests/manager_compat.rs`.

**בדיקות אוטומטיות** (`cargo test --workspace`, `npx vitest run license-manager`):
- יצירת מפתח ראשונית; פתיחה מחדש ללא יצירה מחדש; מפתח אבוד אינו מוחלף בשקט.
- הנפקת רישיון קבוע; הנפקת רישיון מוגבל בזמן; דחיית מזהה מחשב לא תקין.
- אימות הרישיונות במנוע של Hours-Cal; רישיונות רבים באותו מפתח.
- שמירת הרשומה בין הפעלות; גיבוי ושחזור במחשב חדש; דחיית גיבוי ששונה.
- תהליך ההפעלה של המחשב שלך לפני האכיפה.
- סריקה שהמפתח הפרטי אינו מופיע באף קובץ או נתון שיוצא מהליבה.
- בדיקת קבצי ההתקנה: המפתח הפרטי ומנהל הרישיונות אינם נמצאים בהתקנת Hours-Cal, ואין מפתח בהתקנת מנהל הרישיונות.
